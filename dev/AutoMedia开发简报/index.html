    AutoMedia 开发简报¶

    性质：方向简报（由首席助手基于最终发起人的 expectation 形成） 用途：交给 coding agent 核对代码现状 → 由其形成自己的开发方案 本简报不含实现路径——怎么实现由 coding agent 决定

    一、Expectation（最终发起人的期望，最高优先）¶

    终局形态¶

    内核（能力本身）+ 私有部署优先，兼容 SaaS 与服务：

    层 内容
    内核 可配置的标准 + 执行引擎（这是能力本体，不随交付方式变）
    外壳 1 私有部署（先做——兼容性最强、最快能签单）
    外壳 2 SaaS（有客户后加多租户/计费）
    外壳 3 服务（用同一内核帮客户做，无需产品化）

    首个成果¶

    能对外演示的完整 demo——采集端与生产端真跑通（不是概念演示，是实际运行的层级）。

    商业模式¶

    卖"内容符合标准"的保证能力，不是"帮你写内容"。

    目标客户（假设）¶

    品牌代理 / 内容团队——有品牌标准、需要稳定产出的组织。

    时间¶

    不设时间节点。持续开发，与 AutoInfo 并行推进。

    二、为什么（商业依据）¶

    事实 数据来源 含义
    "AI 写作工具"定位已死 Jasper 营收 $120M→$55M，估值 $1.5B→$55M ❌ 不做"帮你写"
    质量门控是空白 现有玩家只有企业级（Writer $30 万/年）或开源单体 ✅ 我们的位置
    无人串成完整流水线 没有一家把"采集→生成→强制质检→发布"做成默认流程 ✅ 我们的位置
    理论已被公开 Explorium 五门理论、CheckApp 开源 ⚠️ 窗口有限
    国内价格地板低 ¥57-99/月 → 出海优先
    企业级能收溢价 Writer NRR 160%、$30 万/年合同 ✅ 质量/一致性可定价

    三、本阶段方向（做什么）¶

    1. 门控产出可交付的合规报告——让客户看见"哪不达标 / 为什么 / 怎么改"（这是付费理由本身）
    2. 稳定性与无人值守——从"能跑"到"能连续跑不出错"
    3. 能让客户找到我们——用自身内容生产能力 + 本地化能力获客
    4. 可定制性——品牌/行业标准可配置，引擎通用（同一内核服务不同客户）
    5. 信任凭证——前后对比案例（证明"用了之后确实更好"）

    四、边界（明确不做）¶

    • ❌ 不做通用"AI 写作/生成"功能（已商品化）
    • ❌ 不增加门控数量（已有 33 个，够用；客户看不见更多门是没意义的）
    • ❌ 不增加平台适配数量（已有 11 个真实 API 自动化）
    • ❌ 不做付费端/计费系统（等有客户再设计）
    • ❌ 不重写现有架构

    五、验收标准（业务视角）¶

    • 非技术客户能看懂报告：哪不达标、为什么、怎么改
    • 报告可作为交付物给第三方（含依据）
    • 能说清"我们为某行业提供合规流水线"（不是"我们有个工具"）
    • demo 真跑通：采集端 + 生产端实际运行
    • 同一内核对不同客户可配（定制客户 A/C 的内容），不需要改代码

    六、红线¶

    • 现有能力不得减少（33 个门控 / 20 个平台适配 / 4,580 测试函数 / Omni Triad）
    • 任何触及现有能力的改动，需满足"阻碍赚钱"判据（阻碍交付 / 阻碍获客 / 阻碍维持），且逐项批准
    • 底线：项目为赚钱服务——如果现有设计确实挡了财路，那是要面对的问题，不是要保护的资产

    附录：现状事实（供核对，非方向指引）¶

    ⚠️ 以下仅为客观事实描述，不含任何改造建议。coding agent 应自行核对并判断。

    项 事实
    代码规模 62,461 LOC 核心 / ~183,000 LOC 总 / 737+ Python 文件
    测试 4,580 个测试函数（247 文件）
    质量门 33 个（文案 / 视频 / 生命周期 / 分发 / 再利用）
    接口 SDK + CLI（19 命令）+ MCP（68 工具）
    平台适配 20 个（11 个真实 API 自动化 + 8 个 manual-stub + 1 通知）
    品牌配置 已有 brand_profile.yaml、品牌 schema、品牌 MCP 工具
    报告基础 已有 pipelines/gate_report.py、validation/report.py
    检查逻辑 检查项以函数形式写在 Gate 类内（如 G3BrandCTA 内 6 个 check 函数）
    其他 Director 模式（HITL 审批）、6 层配置、AES-256-GCM 凭证库、Omni Triad 集成
    CLI 实测 automedia --help 正常（exit=0）
